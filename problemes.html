Problèmes techniques

Problèmes généraux

  1. Je ne peux pas trouver les fichiers de données. Vérifiez d’abord :
    • que vous travaillez dans le dossier LNG1100 décompressé, et non dans LNG1100.zip;
    • que vous avez ouvert RStudio en double-cliquant sur LNG1100.Rproj;
    • que file.exists("donnees/villes.csv") retourne TRUE;
    • que le fichier recherché se trouve dans le bon sous-dossier.
    Si le test retourne FALSE, fermez RStudio, retrouvez le dossier LNG1100 décompressé, puis ouvrez de nouveau LNG1100.Rproj. Consultez les instructions de préparation pour revoir la structure du projet.
  2. L’installation de tidyverse ne fonctionne pas. Vérifiez votre connexion Internet, redémarrez RStudio, puis exécutez de nouveau install.packages("tidyverse") dans la console. Lisez attentivement le message d’erreur si l’installation échoue encore. En cas de problème majeur, utilisez temporairement le plan de secours avec Posit Cloud; il faudra aussi y exécuter install.packages("tidyverse") avant library(tidyverse).
  3. Posit Cloud ne fonctionne pas. Posit Cloud est seulement un plan de secours : continuez normalement dans le projet local ouvert avec LNG1100.Rproj. Vous pouvez vérifier l’état des serveurs sur https://status.posit.co.
  4. Le code ne marche pas! Voici quelques origines de ce type de problème :
    • lisez le message d’erreur attentivement et collez-le sur Google/ChatGPT s’il n’est pas clair;
    • R n’est pas capable de trouver les objets ou les fichiers que votre code utilise. Dans ce cas-là, il faut s’assurer que vous avez créé l’objet pertinent avant de l’utiliser dans votre code;
    • votre code n’est pas correct. Vérifier les lettres majuscule/minuscule, les parenthèses, les noms des variables, etc. Si vous utilisez un code de référence (p. ex., nos pages supplémentaires), comparez attentivement les codes; cherchez des fautes de frappe, etc.;
    • Si vous êtes 100% certain que votre code est correct, vous pouvez essayer de redémarrer R (Session > Restart R);
    • vous pouvez certainement coller votre code sur ChatGPT pour trouver le problème. C’est la dernière option : vous devez essayer de trouver les problèmes vous même (c’est une compétence très importante). Il faut également garder à l’esprit que certains types de problèmes dépendent de votre structure de fichiers. Donc, ChatGPT ne sera pas capable de vous aider dans ce type de situation.
  5. Mes références ne sont pas affichées dans le document (Quarto). Vérifiez votre préambule et assurez-vous que votre fichier de références bib est correct, notamment sans guillemets, et que sa localisation est correcte aussi. Si vous utilisez le modèle dans notre dépôt Git, vous n’aurez pas ce type de problème.
  6. Une erreur qui n’existait pas auparavant. Par exemple : Error in select(...). Si on charge plus d’une extension qui contient des fonctions de noms identiques, on peut arriver à ce type de problème. C’est le cas ici : tidyverse a une fonction appelée select() (c’est une fonction de l’extension dplyr, chargée avec tidyverse). Quand on parle des modèles logistiques, on utilise souvent la fonction invlogit() de l’extension arm. Cette extension contient aussi une fonction select() (!), qui sera priorisée par R. C’est pourquoi vous avez ce type de problème. Pour régler le problème, il y a deux options : déchargez arm en exécutant detach("package:arm", unload = TRUE) ou ajoutez le préfixe dplyr:: à la fonction select() : dplyr::select(). Cela clarifie que vous voulez utilisez la fonction select() de l’extension dplyr.
  7. J’ai un problème pour importer un fichier csv. Si vous avez un fichier csv, il faut vérifier quel type de séparation de colonnes le fichier utilise. S’il utilise une virgule, on utilise la fonction read_csv(); s’il utilise un point-virgule, read_csv2(). N’utilisez jamais Excel pour visualiser votre fichier csv avant de l’importer dans RStudio pour éviter des problèmes.
  8. Mes tableaux ne marchent pas dans le document PDF produit avec Quarto. Bien que Quarto nous permette de créer plusieurs formats de fichiers, il faut dire que chaque format a ses propres particularités. Un document HTML, par exemple, est dynamique, tandis qu’un document PDF sera toujours statique. Il y a donc des extensions qui ne marcheront pas dans les deux. Des tableaux en sont un exemple : les tableaux utilisés dans un document Quarto HTML peuvent ne pas fonctionner correctement si vous décider de créer un document PDF en changeant le format dans le préambule de votre document. Encore une fois, utilisez le modèle fourni tel quel et vous n’aurez pas de problèmes.

Évaluations du cours

Vous pouvez consulter la politique du cours concernant les problèmes techniques sur Brio (Évaluation). RStudio installé sur votre ordinateur est la méthode normale pour le cours; Posit Cloud est seulement un plan de secours. Vous êtes responsable de préparer et de vérifier votre environnement de travail avant une évaluation. La politique officielle et les consignes applicables sont celles publiées sur Brio.

Si vous éprouvez des difficultés avec un questionnaire sur monPortail, vous pouvez en tout temps fermer et réouvrir la fenêtre ; vos réponses ne seront pas perdues. Cependant, rappelez-vous que vous êtes responsable des conditions dans lesquelles vous faites votre évaluation. En cas de perte de connexion avec le serveur, une reprise pourra être organisée seulement si le problème provient des serveurs du Portail. Assurez-vous donc de ne pas surcharger votre bande passante lors de la passation de vos évaluations.
